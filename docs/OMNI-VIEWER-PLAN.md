# 옴니 뷰어 계획 (확정본)

채팅을 미연시처럼 본다: 배경(삽화) · 서 있는 캐릭터(감정 에셋) · 대사창(TTS) · 상태창 · 선택지.
PocketRisu, 원본 Risu, 폰, PC 모두 같은 코드로 돈다. 끄면 하는 일이 0이다.

## 원칙

- S2D.VN · 칵테일은 **구조 아이디어만** 참고한다. 코드·주석은 한 줄도 가져오지 않는다.
- 저장 키는 바꾸지 않는다(새 키만 추가). 고정 UI(`vendor/`)는 빌드 패치로만, 바늘이 어긋나면 빌드 실패.
- 새 API는 `tools/parity/scenario.mjs`에 단계를 추가한다. 새 가드는 일부러 깨서 빨개지는지 본다.
- 꺼져 있으면 아무 리스너·타이머·브리지 호출도 없다(PocketRisu 속도 유지).

## Risu 구조에서 렉이 생기는 곳과 대책

| 원인 | 사실 | 대책 |
|---|---|---|
| 브리지 왕복 | 플러그인의 Risu 화면 조작(SafeElement)은 호출마다 iframe 왕복. 폰에서 비쌈 | 뷰어 틀은 한 번 만들고, 장면 전환은 `setInnerHTML` 한두 번. 움직임은 전부 CSS |
| 이벤트에 대상이 없음 | `addEventListener`는 문서 전체에 걸리고 target이 없어서 좌표로 판정(`hitHost`)해야 함. 버튼마다 `getBoundingClientRect` | 뷰어는 고정 배치라 버튼 사각형을 그릴 때 한 번 재서 캐시. 탭 한 번에 브리지 호출 0 |
| 이미지 전달 | `setInnerHTML`은 DOMPurify가 `blob:`을 지움, `setAttribute`는 `x-*`만 됨 → 화면엔 `data:` URL만 가능(`src/storage/image-urls.ts`) | 삽화는 채팅에 이미 그려진 `<img>`를 `cloneNode`로 복제(픽셀 이동 0). 입상은 세션당 한 번만 data URL로 보내고 노드를 재사용(감정 전환은 속성 하나) |
| 스트리밍 재렌더 | Risu는 청크마다 메시지 목록을 다시 그림 | 뷰어가 덮는 동안 뒤 채팅은 최근 N개만 남기고 숨김(스타일 한 줄). 장면 갱신은 문단이 확정될 때만(`settledWhileStreaming`) |
| 캐릭터 쓰기 | `setCharacterToIndex`는 채팅까지 통째로 다시 씀. 스트리밍 중엔 위험 | 감정 에셋 등록은 기존 대기열(`writeCharacter`, shot-character)에 실어 답장이 끝난 뒤 한 번에 |

## 1단계 · 에셋 모드 분리

- 고정 UI의 `Mode` 선택(삽화/에셋)을 빌드 패치로 지움 → 삽화 전용.
- `migrateSettings`: 저장된 `card.mode: 'asset'` → `'illustration'`(키 그대로).
- `generation.ts`의 `card.mode === 'asset'` 분기(흰 배경 태그)를 제거. 그 역할은 3단계 감정 에셋이 맡는다.

## 2단계 · 스트리밍 모드 보강 (삽화·에셋 공용)

「스트리밍 중 태그 생성」 아래 토글 3개(새 키, 기본값은 아래):

1. **새 캐릭터를 맨 앞에 쓰기**(기본 켬) — 응답 맨 앞에 `[[inxc]]{"new_characters":[…]}[[/inxc]]` 한 블록.
   스트림에서 닫히는 즉시 캐릭터 목록에 등록(그림 작업 없음). 빠진 사람은 기존 규칙대로 첫 블록에.
   표시·요청·TTS·본문 분석에서 숨김(토큰 가드, display/editprocess 규칙, `INLINE_SHOT_MASK_SOURCE` 계열).
2. **에셋 메타데이터 참고**(기본 켬) — `collectGenerationAssets`를 그대로 써서 **아직 외형이 없는 사람**의
   NAI 메타데이터 블록을 채팅 상태(`inlineTagState`)에 실음. 봇별 캐시, 요청 직전에 읽지 않음.
3. **메타데이터에 외형이 없으면 사진도 보내기**(기본 끔, 이미지 읽는 모델 전용) — 머리·눈 태그가 없을 때만.
   Risu 메인 요청에 이미지를 실을 수 있는지 먼저 확인, 안 되면 이 토글은 숨김.
- 이미 등록된 캐릭터의 외형은 덮어쓰지 않는다(먼저 등록된 쪽 우선).

## 3단계 · 감정 에셋 (TTS용, LLM 호출 없음)

- **프롬프트** = 에셋 선행 프롬프트 + 캐릭터에 묶인 스타일 프리셋(없으면 활성 프리셋) + 캐릭터 외형 태그
  (`characterPreviewTags`) + 감정 태그(예 `2::smile::`) + 자세 태그(예 `2::cowboy shot::`) + (V5) 투명 배경 + 후행 프롬프트.
  생성은 `generateT2i` 한 번. **LLM은 부르지 않는다.**
- **외형 출처**: 삽화 캐릭터 목록 → 에셋 메타데이터. 둘 다 없으면 "외형 없음"으로 표시하고
  버튼(기존 캐릭터 만들기)으로만 채움.
- **감정 수집**: TTS 대사 머리 `이름 (happy): "…"`의 억양 단어. 감정 표(동의어 → 기본 표정 12~16개)로
  묶어서 한 캐릭터당 그림 수를 고정. 표에 없는 단어는 "미분류"로 보여주고 자동 생성은 안 함.
- **기존 에셋 찾기**(토글 「봇에 있는 기존 에셋 쓰기」, 기본 켬): 이름·별칭·트리거 × 감정, 앞뒤 순서,
  `_` ` ` `.` `-` 구분 모두. 봇 캐릭터 에셋 → Risu 감정 이미지 → 켜진 모듈 에셋(읽기만).
- **저장**: 봇 캐릭터 에셋 `이름_감정.webp`. 등록은 답장이 끝난 뒤 한 번에. 뷰어는 등록 전에도 로컬 사본으로 바로 씀.
- **없을 때**: 기본 표정을 먼저 보여주고, 자동 생성(토글)이 끝나면 교체.
- **화면**: TTS 창 맨 위를 **TTS · 에셋 · 뷰어**로 나눔. TTS 캐릭터 팝업에 **음성 · 에셋** 탭.
  에셋 탭: 감정 칸 격자(있음/없음/생성 중/다시 생성), 감정 표·자세·모델(V4.5/V5)·크기·선행/후행 프롬프트.

## 4단계 · 옴니 뷰어 (오버레이)

- `<body>`에 붙인 고정 오버레이가 채팅 영역만 덮음(입력창은 Risu 것 그대로). 채팅 화면이 다시 마운트돼도
  1~2초 주기 위치 확인으로 따라감(TTS 뷰어와 같은 방식).
- **데이터는 화면이 아니라 원문에서**: 메시지 원문(+스트리밍 텍스트)을 TTS 분할기로 나눔 → 화자·감정·대사/나레이션.
  삽화 토큰 위치 = CG가 뜨는 문단. 메시지 div를 읽지 않으니 Risu 재렌더와 무관.
- **화면**: 상단(날짜·시간·장소 칩, 상태창 버튼, ♪, 닫기) · 배경 · 입상 최대 2명(말하는 쪽만 밝게) ·
  대사창(이름 + 글자 효과는 CSS) · 하단(자동 · 로그 · 스킵).
- **진행**: 탭 → 다음 문단 + TTS 재생. 자동 모드는 음성이 끝나면 넘어감. 로그에서 문단을 누르면 그 장면으로.
- **스트리밍**: 확정된 문단부터 장면으로 이어 붙임. 아직 안 끝난 문단은 "…" 표시.
- **상태창·선택지**: 뷰어 설정에서 봇마다 마지막 메시지의 덩어리 후보를 보여주고 역할(상태창/선택지/숨김)을 고름.
  원본 요소를 숨긴 채팅 위로 띄워(복사하지 않음) Risu 버튼·Lua 트리거가 그대로 동작.
  띄우기가 그 봇에서 안 먹히면(조상 transform 등) "선택지 보기" → 뷰어를 잠깐 내리고 그 위치로 스크롤.
- **날짜·장소**: 원문 상태줄(`[날짜 ◆ 시간 ◆ 장소]` 류)을 최근 메시지부터 칸별로 이어받아 파싱.
- **켜기**: Risu 채팅 메뉴·햄버거 버튼. 다시 열면 마지막으로 보던 장면부터.

## 5단계 · 유튜브 BGM + 주소 BGM 즉시 재생

- 우리 display 처리기가 마지막 메시지에 `youtube.com/embed/…?enablejsapi=1` iframe을 심음(정화기 허용 경로) →
  본문으로 한 번 복제해 고정(옮기지 않음) → postMessage로 재생·정지·음량(TTS 덕킹)·곡 변경.
- BGM 목록에 출처 `youtube`(영상 ID) 추가. 기존 주소·파일 BGM은 그대로.
- 창은 기본 작게 보임. 「화면 밖으로 숨김」 토글 + "유튜브 약관 위반 가능, 책임은 사용자" 경고.
- 모바일 첫 재생: 사용자의 첫 탭 순간에 재생 명령. `allow="autoplay"` 유지 여부는 실기기 확인.
- (추가) 주소 BGM을 다 받기 전에 `<audio>`로 바로 흘려 재생해 보고, 막히면 지금 방식으로 자동 후퇴.

## 검증

- 단위: 감정 표/이름 매칭/프롬프트 조립/장면 분할/상태줄 파싱(순수 함수, `domain/`).
- 호스트: Playwright 제한 SafeDOM 하네스(`tests/tts-host.test.mjs` 방식)로 뷰어를 띄워
  **장면 전환당 브리지 호출 수 상한**, **탭당 사각형 읽기 0**을 가드로 검사(일부러 깨서 빨개지는지 확인).
- 스트리밍: 청크를 흘려 넣어 문단 확정·`[[inxc]]` 등록·숨김을 검사.
- 실기기: PocketRisu(폰 닫혀 있을 때, SFW, 끝나면 탭 닫기) + 원본 Risu.

## 구현 중 확인할 것

- Risu 메인 요청에 이미지 첨부 가능 여부(2단계 사진 토글).
- 정화기가 유튜브 iframe의 `allow` 속성을 남기는지.
- V5 투명 배경 태그 결과.
- 원본 요소 띄우기가 Risu 채팅 컨테이너(transform/contain) 안에서 먹히는지.
