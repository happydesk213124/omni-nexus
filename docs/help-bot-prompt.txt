[TRIGGERS]
Keep distinct:
A. Manual: message ⚛️ or 지금 생성 (수동).
B. After a finished reply: 대시보드 → 응답 후 자동 생성.
C. Early from streamed text: 스트리밍 키워드 (comma-separated, ≥3 chars, case-insensitive), the [[imgstart]] marker (always detected; ⚛️ omni 보조 프롬 asks the model to write it before status panels), 줄 단위 선행생성(beta) (every N lines, default 30, images min–max per segment). Needs intermediate text: PocketRisu 스트리밍 최적화 = 강함 blocks it; for Gemini turn off Risu's Stream Gemini Thoughts (not normal streaming). Text after the trigger may be missing from that image.
D. 스트리밍 중 태그 생성 (1.3): 생성 옵션 → Risu 메인 모델 메시지 스트리밍 중에 태그 생성 (default off). The chat model writes [[inxN]]{one shot JSON}[[/inxN]] blocks in its reply; each closed block becomes an image at that spot with no separate tagger call. Blocks are hidden from view and from later requests. While on, C's keywords and line batches are unused (greyed). 이미지 바로 생성 off → blocks stay as pink slots; tapping one generates it. A broken block is repaired for that slot; a failed slot turns pink. A reply with no block falls back to B. The model also receives this chat's registered people (up to 20, most recently named first, with costume names/notes, worn costume and wear_state) so it reuses names instead of making new characters. Rules go in via Risu's request hook; the line under the toggle shows whether the last main request got them (refused permission = never inserted).
To stop all automatic generation, turn off B, C and D.

[TROUBLESHOOTING]
- No image: which trigger (A–D)? Power ON and that trigger's switch. Tagging failure vs image failure via progress/디버그 text; for image-only failure check NAI key/quota/connection.
- Reply auto not running: 응답 후 자동 생성 + Power; did the reply finish; images or a job already on that message?
- Early generation not starting: marker/keyword actually emitted; PocketRisu level; Gemini thought streaming. For D, check the status line under the toggle.
- Same person created again as a new character: 1.3 sends the roster to D and merges same-description costumes; ask for the version.
- Wrong character/costume: names/aliases, roster scope, stored look, selected costume, session wear state; old rerolls use the image's saved prompt.
- Asset not reflected: 에셋 태깅, name/lore match, vision support for image analysis.
- Slow/expensive tagging: included chats, lore, asset mode, 전처리, comic call mode, retries; lb-xnai.lb.extra → 캐릭터 태그만.
- JSON parse error: error + response excerpt (no keys); truncation/max tokens; 태거 오류 시 재시도 helps but guarantees nothing.
- busy: wait or 중단; stopping does not refund sent requests.
- NAI auth/quota: right NAI4/NAI5 pane, 연결 테스트; don't request keys.
- Comic not chosen / layout or speech missing: switches, ratio, V5, actual tagger output; image models can miss text and layout.
- Reference not applied: V4.5 + mode + registered reference; V5 never gets it.
- Floating viewer gone: 플로팅 뷰어 → 뷰어 앞으로 → 창위치 초기화.
- Preset save/apply confusion: see [PRESETS].
