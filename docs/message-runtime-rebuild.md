# 메시지 런타임 변경 기록

2026-09-14. 플러그인 ID와 기존 저장 키를 유지하며, 빌드 결과는 `dist/omninexus.js`다. vendor는 수정하지 않는다.

## 실행 경로

- `native.ready`: 설정·프롬프트 준비. 전체 채팅 스피너 청소와 부팅 기록 저장은 실행하지 않는다. 참고이미지의 실제 바이트 읽기도 `openDb`에서 분리했다. 이미지 관련 설정 화면을 열 때만 해당 미리보기를 준비한다.
- `message-runtime.js`: `.chattext` 끝 footer 하나를 소유한다. 기존 절대 위치 팬 생성기와 주기적 팬 재검사는 실행하지 않는다. 본문 비교 없이 등록한 캐릭터·채팅·메시지 번호로 작업을 보낸다. 편집 중에는 footer를 만들지 않는다.
- 태거 요청을 시작한 뒤 기존 박제 참조만 제거한다. 에셋은 삭제하지 않는다. 기존 스피너 위치를 재사용하고 장수 차이만 반영한다.
- 생성 중에는 각 슬롯에 base64 미리보기를 붙인다. 에셋 저장을 마친 성공 샷을 작업 종료 시 한 번 확정한다. 저장된 형태는 `[[@inrayspinner::job_shot::w::h]][[@inray::id::asset::w::h]]`다.
- 디스플레이 모듈은 쌍을 먼저 처리한다. 한 프레임·한 이미지·한 동작바를 출력하며 미완성 슬롯은 재시도 가능한 자리로 남긴다. 에셋 이미지 디코딩이 확인된 뒤 미리보기 노드와 메모리를 해제한다.
- `scroll-runtime.js`: 메시지/에셋 등록 쓰기 구간만 담당한다. 서버 응답 대기와 미리보기 겹침에는 화면을 고정하지 않는다. 새 DOM에서 본문·메시지 위치를 다시 찾고, 사용자 입력과 채팅 전환을 우선한다. 기존 보정 함수의 실행은 차단했다.
- `writeMetrics()`는 설정·채팅·캐릭터·모듈 쓰기 횟수, 실패 횟수, 누적 시간만 메모리에 보관한다. 내용·API 키·이미지 바이트는 기록하지 않는다.

## 로컬 검증과 한계

- 독립된 두 backend 인스턴스로 같은 저장소를 열었다. 최초 설치 저장은 2회, 두 번째 부팅의 설정/채팅/모듈 저장은 0회였다. 두 번째 부팅에서 참고이미지 바이트 읽기가 없음을 검사한다. 이는 작은 로컬 호스트 모형의 결과이며 실제 사용자 저장소의 속도 측정이 아니다.
- 320/1440/3440px footer 위치·줄바꿈·중복 방지·편집 후 복구와 SafeElement의 `x-*` 속성 제약을 검사한다.
- 살균된 모듈 HTML에서 네 장 순차 미리보기, DOM 재생성 후 복구, 프레임 크기, 완료 후 미리보기 해제를 검사한다.
- 로컬 좌표 복원, 수동 입력, 채팅 전환, 쓰기 실패 시 관찰자/리스너 해제를 검사한다. 실제 Risu의 렌더링 지연·브라우저 스크롤 동작은 별도 확인이 필요하다.

## 패리티의 의도된 차이

이전부터 적용된 에셋 중심 저장 동작을 명시적으로 검사한다. 생성 파일 안의 레시피는 실제 전송한 생성 요청과 같아야 하며, 리롤은 현재 프리셋 대신 저장된 레시피를 유지해야 한다. 이미지 레시피 추가로 파일 바이트 수가 증가하는 것은 허용하되 갤러리와 탐색기의 바이트 수 일치를 검사한다. 박제 메시지가 없는 fixture에서 위치를 지어내지 않으며, 새 이미지는 방별 카드 팩이나 작업 기록으로 중복 저장하지 않는다. 나머지 필드는 이전 버전과 계속 비교한다.
