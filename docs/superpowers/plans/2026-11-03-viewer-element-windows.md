# 옴니 뷰어 요소 창 계획

> 상태: 계획 (2026-11-03, 1.4.5 다음). 아래 「확인 필요」에 답을 받은 뒤 구현한다.

## 목표

- 등록한 요소(상태창 같은 것)를 **복사본이 아니라 채팅 속 진짜 요소 그대로** 뷰어 위 창에 띄운다. 그래서 상태창 탭, Risu 버튼(트리거·{{button}} 같은 것)까지 눌린다.
- 요소마다 창이 하나씩 뜬다. 여러 요소를 따로 관리한다.
- 창에는 제목줄(요소 이름, ▾ 접기 / ▸ 펼치기)만 있다. **닫기·전체화면은 없다.** 전체를 숨기는 건 지금처럼 오른쪽 **요소** 버튼이 한다.
- 제목줄을 끌어서 옮긴다(편집 모드가 아니어도). 창 위치와 접힘은 봇마다, 요소마다 기억한다.
- 다음 챗이 현재 답장의 **부속 챗**이면 그 챗의 요소도 현재 답장의 창으로 띄우고, 부속 챗은 뷰어에서 답장으로 세지 않는다.

## 하지 않는 것

- 닫기(✕)·전체화면 버튼.
- 다른 플러그인이 자기 iframe에 그리는 요소. Risu 채팅 화면 안에 있는 요소만 다룬다.
- 선택지 기능은 바꾸지 않는다.

## 지금 구조

| 파일 | 하는 일 |
|---|---|
| `src/viewer/elements.ts` | 편집(요소 등록), 스티커(채팅 요소를 cloneNode로 복사해 뷰어에 붙임), 선택지, 스티커 끌기 |
| `src/domain/viewer/elements.ts` | 답장 HTML에서 요소 종류 찾기 (findElementKinds) |
| `src/storage/viewer-elements.ts` | 봇별 규칙 `omniviewer.elements`: role(sticker/choice), x, y, scale, hidden, always |
| `src/viewer/omni-viewer.ts` | 채팅 접기(foldCss: 최신 메시지 2개만 남김), 탭 나누기, 답장 목록(charIndexes: role이 char인 메시지 전부), 화면 중앙으로 열기 |

스티커는 복사본이라 Risu가 버튼에 붙여 둔 처리가 없고, id가 원본과 같아 label·라디오 탭은 원본(뷰어 뒤)을 바꾼다. 그래서 지금은 접기·펼치기(details)만 동작한다.

## 설계

### 1. 진짜 요소 띄우기

- 등록한 요소의 원본 노드에 x- 표시(예: x-vn-win="키")를 붙인다. SafeDOM으로 쓸 수 있는 건 x- 속성뿐이라 표시도 x-로 한다.
- 뷰어가 Risu 문서에 넣는 스타일 한 장에서 그 표시를 `position:fixed`, 창 본문 좌표(left·top·width·max-height), 뷰어보다 높은 z-index로 띄운다. 요소가 창보다 길면 창 안에서 스크롤한다.
- 원본의 조상 가운데 fixed를 가두거나 쌓임 순서를 막는 스타일(transform, filter, perspective, contain, will-change, backdrop-filter, z-index, isolation, opacity, clip-path, mask)은 조상에도 x- 표시를 달고 같은 스타일 장에서 잠깐 푼다.
- 인라인 스타일을 고치지 않고 표시와 스타일 장만 쓰므로, 접거나 닫을 때 표시만 떼면 원래대로 돌아간다. 되돌릴 값을 따로 기억하지 않는다.
- 원본은 계속 그 채팅 메시지 안에 있으므로 누르면 Risu가 평소처럼 처리한다.

### 2. 창

- 뷰어 안에 창 틀을 그린다: 제목줄(요소 이름, ▾/▸)과 본문 자리.
- 본문 자리의 크기를 재서 원본을 그 위치에 맞춘다. 창을 옮기거나 화면 크기가 바뀌거나 펼칠 때 다시 잰다.
- 접기: 제목줄만 남기고 원본 띄우기 표시를 뗀다. 펼치기: 다시 붙인다.
- 끌기: 제목줄을 누른 채 움직이면 창이 따라오고, 놓으면 화면 비율(%)로 저장한다. 지금 스티커 끌기와 같은 방식이고, 움직이는 동안만 pointermove를 듣는다.
- 탭 나누기:
  - 창 본문을 누른 탭은 원본(Risu)의 것이다. 이야기를 넘기거나 줄을 완성하지 않는다(지금 onSticker와 같음).
  - 제목줄 탭은 접기·펼치기다. 끌기를 끝낸 직후의 클릭은 무시한다.
- 편집 목록의 칩: 「스티커」를 「창」으로 부르고, 📌 항상·숨김·크기는 그대로 둔다.

### 3. 저장

- 규칙의 role 값 `sticker`는 그대로 둔다. 저장된 키와 값을 바꾸면 이미 등록한 요소가 사라진다(화면 이름만 「창」으로 바꾼다).
- 새 필드 folded(접힘)만 더한다. 없으면 펼친 것으로 읽는다.

### 4. 채팅 접기와 같이 쓰기

- 지금 접기는 최신 메시지 2개만 남긴다. 접힌 메시지 속 요소는 띄울 수 없으므로(부모가 display:none), 무대에 올린 답장과 그 부속 챗은 접기에서 뺀다(`:has()`로 그 메시지 번호를 지정).
- 그러면 옛 답장을 볼 때도 창이 뜬다. 펼쳐 두는 메시지가 한두 개 늘 뿐이라 비용은 거의 그대로다.

### 5. Risu가 다시 그릴 때

- 스트리밍·수정·다시 생성 때 Risu가 메시지를 다시 그리면 표시가 붙은 노드가 새 노드로 바뀐다.
- 다시 찾아서 표시를 붙이는 때: 스트리밍 틱이 끝날 때, 답장이 저장될 때(output), 박제 뒤 다시 읽을 때, 그리고 창이 떠 있는 동안 2초마다 표시가 남아 있는지 한 번 확인한다(querySelector 한 번).

### 6. 부속 챗

부속 챗 조건 (모두 만족):

1. role이 char다.
2. 현재 답장 바로 다음이다. 사이에 유저 메시지가 끼면 부속이 아니다.
3. 라이트보드 태그나 편집에서 등록한 요소가 있다.
4. `이름: "대사"` 대사 줄이 없다. TTS 줄 읽기 기준으로 화자가 있는 대사가 0줄이다.

- 부속 챗이 연달아 여럿이면 조건이 깨질 때까지 전부 현재 답장에 붙인다.
- 판정 재료: 대사 줄과 라이트보드 태그는 메시지 원문으로, 등록한 요소는 그 메시지 화면에서 본다. 화면은 이웃 메시지 한두 개만 읽는다.
- 뷰어에서 부속 챗은 답장으로 세지 않는다: ◀ ▶, 메시지 목록, 보던 곳 모두 건너뛰고, 화면 중앙으로 열 때 부속 챗이 가운데면 앞 답장부터 연다.
- 판정은 src/domain/viewer 아래 새 순수 함수로 둔다(메시지 목록, 대사 판정, 요소 유무 → 부속 범위). 단위 테스트로 지킨다.
- 대사 없이 서술만 있는 진짜 답장은 조건 3에서 걸러져 부속이 되지 않는다.

### 7. 성능

- 창을 띄우는 일은 속성 몇 개와 스타일 한 장을 바꾸는 것뿐이다. 창 좌표는 열 때, 옮길 때, 펼칠 때, 화면 크기가 바뀔 때만 잰다.
- 등록한 요소가 없는 봇은 지금처럼 아무것도 읽지 않는다.

## 위험

- 봇 CSS가 부모 폭에 기대는 요소는 창 폭에서 모양이 조금 달라질 수 있다. 창은 요소의 원래 폭으로 시작한다.
- Risu 자체의 고정 UI(입력창 등)와 겹칠 수 있다. 창은 뷰어 영역 안으로만 옮길 수 있게 한다.
- 스트리밍 중에는 창 안이 잠깐 깜빡일 수 있다.
- 조상 스타일을 푸는 동안 뒤의 채팅 배치가 바뀐다. 뷰어에 가려 안 보이고, 닫으면 원래대로다.

## 테스트

- 도메인: 부속 챗 판정. 조건마다, 연속 부속 챗, 유저 메시지에서 끊김, 서술만 있는 답장은 부속 아님.
- 뷰어(SafeDOM 목):
  - 창을 띄우면 원본과 조상에 표시와 스타일이 붙는다.
  - 접으면 표시가 떨어지고, 닫으면 전부 떨어진다.
  - 제목줄 끌기로 위치가 저장되고, 본문 탭은 이야기를 넘기지 않는다.
  - 무대 답장과 부속 챗은 접기에서 빠진다.
  - 다시 그려진 노드를 다시 찾는다.
  - 부속 챗은 ◀ ▶와 화면 중앙에서 건너뛴다.
- 배치·타이밍 테스트는 일부러 깨뜨려 실패하는지 확인한다.

## 확인 필요

1. 라이트보드 챗 원문(태그 모양). 태그 판정에 쓴다. 없으면 「등록한 요소가 있음」만으로 판정한다.
2. 스티커(복사본) 방식을 선택지로 남길지, 창으로 완전히 바꿀지.
3. 창의 처음 크기: 요소의 원래 폭 그대로, 또는 화면의 몇 %.
4. 부속 챗의 글은 채팅에서 TTS가 나레이션으로 읽는다. 뷰어에서 건너뛰는 것과 별개로 그대로 둘지.
