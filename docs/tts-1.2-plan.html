01. 이번 검수본

TTS 설명은 기존 우상단 ? 도움말에 통합합니다. 설명을 켠 뒤 항목에 마우스를 올리거나 키보드로 선택하면 기존 헤더 도움말에 표시합니다. 설정 본문의 반복 안내는 줄이고 실제 오류·상태 및 시안 표시는 유지합니다. TTS 설정은 PC 폭 1000px 이상에서 2열, 좁은 화면에서는 1열입니다.

번역 모델·키 입력은 ‘번역해서 듣기’ 안의 접이식 연결 설정으로 이동합니다. 채팅에는 번역 예시 문구를 붙이지 않습니다. 플로팅 뷰어 닫기 버튼은 제거하고 설정의 표시 ON/OFF와 접기만 유지합니다. 캐릭터 타일은 참조 이미지를 전체 배경으로 쓰고 정보는 투명한 하단에, 트리거워드는 우상단에 표시합니다. 캐릭터 타일은 정사각형으로 이름·트리거워드·글로벌 범위와 이름 아래 선택된 음성 프리셋명 한 줄을 표시합니다. 개별 음량 슬라이더·음성 프리셋·성별·배정 방식은 편집창에 둡니다. 밝은 참조 이미지에서도 글자가 읽히도록 약한 그라데이션과 글자 그림자만 사용합니다. 대사 버튼은 hover·키보드 포커스·누름·재생 중 상태를 색으로 구분합니다.

기존 플러그인 설정창의 헤더·메뉴·다크 모드 틀을 그대로 사용합니다. TTS 사용 전원과 음성 재생 활성화는 네 하위 탭이 있는 줄 오른쪽에 합칩니다. 별도 행은 만들지 않습니다. 좁은 화면에서는 활성화 버튼을 음표 아이콘으로 줄이고 하위 탭은 가로 스크롤합니다. 전원 토글은 비활성화 범위 밖에 두어 OFF 상태에서도 바로 켤 수 있습니다. 전원 OFF에서는 TTS 설정 전체를 즉시 비활성화하고 값은 보존하며, ON에서만 편집합니다. 삽화 전원은 영향을 주지 않습니다. TTS 상단 제목·중복 상태 안내·테스트 이동·구현 계획 링크는 제거합니다. 검수본에서는 기존 설정창의 닫기로 별도 Risu 메시지 모형 화면에 돌아갑니다. 대사 버튼·세로선·플로팅 플레이어는 그 채팅 화면에만 표시합니다.

사용자 음성 프리셋 176개 탐색, 버튼·검색·추가·수정·삭제·JSON 입출력은 시안 메모리 안에서 동작합니다. 플레이어는 8초짜리 무음 상태 시뮬레이션입니다.

실제 음성 생성·번역·캐시 저장·캐릭터 자동 등록·Risu 설치·기존 TTS 탭 교체는 아직 하지 않았습니다. 기존 설정·배포 버전을 변경하지 않았으며 1.2.0은 기능 검수 후 출시 목표입니다.

원본 프리셋은 여성 125개, 남성 51개입니다. ‘카미죠 토우마’와 ‘미야 아츠무’의 Fish ID가 같아 중복으로 표시합니다. 임의로 삭제하거나 합치지 않으며 ‘추론’ 표시도 보존합니다.

02. 확정한 사용 방식

  • 독립 전원: 삽화 Power OFF + TTS ON 가능. 이미지 생성 완료를 기다리지 않음.
  • 네 탭: TTS 설정 / 캐릭터 / 음성 목록 / 모델 설정. 기존 FISHTTS 자리는 TTS 모델 설정으로 이동.
  • 화자: 이름·억양 모듈에서 나온 이름만 수집. TTS 트리거워드에 있으면 기존 음성, 없으면 그 화자만 보조 LLM에 전달.
  • 나레이션: 이름·억양 표식이 없는 본문. ‘재생과 읽기’에는 ON/OFF만 두고, 음성 지정은 음성 목록에서 선택한 한 항목에 적용합니다. 설정 탭의 나레이션 음성 드롭다운은 제거합니다. 이미지 표식·HTML·생각·상태창·코드는 읽지 않음.
  • 재생: 버튼 클릭 / 버튼 마우스오버 / 새 답변 완료 후 자동 재생을 각각 설정. 자동 재생은 기본 OFF.
  • 표시: 이름·억양을 각각 화면에서 숨길 수 있음. 원문 보존. 버튼이 속한 대사 전체 높이에 옅은 세로선.
  • 플레이어: 별도 뷰어 ON/OFF, 이동·접기·이전·다음·재생·일시정지·정지·배속·볼륨. 동시 재생은 한 개.
  • 번역: 끄기 / TTS LLM / Google / DeepL / 사용자 지정 번역 LLM. 일본어·영어·직접 입력. 출발 언어 자동 감지.

목록과 편집: 캐릭터·음성 타일 영역은 남은 화면을 채우고 독립적으로 스크롤합니다. 검색·폴더·선택 작업은 고정합니다. 타일 한 번 클릭은 선택, 선택한 타일 재클릭은 편집이며 반복 수정 버튼은 제거합니다. 음성 목록은 Ctrl/Cmd 추가 선택, Shift 범위 선택과 모바일 다중선택 모드(탭으로 추가/해제)를 제공합니다. 체크 표시로도 개별 선택할 수 있습니다. 나레이션 지정·수정은 한 개 선택일 때, 폴더 이동·삭제는 다중 선택에도 활성화합니다. 삭제는 대상 이름과 개수를 보여준 뒤 확인하며 취소하면 그대로 유지합니다. 폴더 삭제는 음성을 미분류로 옮기고 Fish ID 및 기존 캐릭터·나레이션 배정을 지우지 않습니다.

캐릭터·음성 편집, 자료에서 LLM으로 가져오기, LLM으로 추가, LLM 정리 요청은 기존 캐릭터 팝업처럼 넓은 하단 시트, 상단 전체 접기 버튼, 가로 입력 행, 내부 스크롤을 사용합니다. 자료 가져오기와 목록 변경은 검수 후 적용합니다. 캐릭터 탭의 ‘새 화자 발견 시안’ 박스는 제거하되 자동 음성 배정 설정은 유지합니다.

음성 선택: 캐릭터의 음성 프리셋은 드롭다운 대신 음성 목록으로 이동해 고릅니다. 탭에 ‘음성 목록 (선택 중)’을 표시하고 한 번 누르면 선택, 선택한 타일을 다시 누르면 해당 Fish ID를 넣어 작성 중이던 캐릭터 편집창으로 돌아갑니다. 선택 취소는 기존 음성과 미저장 입력을 보존합니다. 음성 타일은 정사각형이며 긴 이름과 태그는 줄 수를 제한합니다. PC 상단은 검색·분류·정렬·LLM 작업·파일·탐색 링크를 한 줄 도구 모음으로 통합하고 좁은 화면에서 줄바꿈합니다.

바로 미리듣기: 캐릭터·음성 타일 우하단과 편집창의 듣기 버튼은 추가 팝업이나 언어 선택 없이 즉시 고정 문장 ‘안녕하세요, こんにちは, Nice to meet you.’를 요청합니다. 한국어·일본어·영어가 한 문장에 들어가며 LLM/번역 호출은 하지 않습니다. 편집창에서는 아직 저장하지 않은 현재 Fish ID와 음량을 사용하고 듣기가 저장을 대신하지 않습니다. 시험 요청도 전체 Fish 동시 요청 상한과 직접 재생 우선순위를 따릅니다. 같은 모델·ID·문장·생성 옵션은 캐시를 재사용하고 일반 대사와 같은 단일 오디오 출력기를 사용하여 겹쳐 재생하지 않습니다. 클릭 시 오디오 활성화를 시도하고 실제 재생 성공/오류를 구분합니다. 현재 시안의 버튼은 연결 전 안내만 표시하며 실제 Fish 요청이나 소리는 없습니다.

캐릭터 LLM 명령: 캐릭터 탭의 ‘LLM한테 시키기’는 요청문, 로어북 포함·페르소나 포함·삽화 캐릭터 참고 토글, 저장 범위, 보조 모델, 음성 목록에서 프리셋도 배정 토글을 제공합니다. 여러 캐릭터를 한 번에 제안하고 결과를 검수한 뒤 선택 항목만 추가합니다. 번호가 붙은 최소 음성 후보 목록을 보내고 결과는 이름·트리거워드·성별 및 선택한 프리셋 번호로 제한합니다. Fish ID·음성 설명을 재출력하지 않으며 번호는 요청 당시 후보표로 해석합니다. 알려지지 않은 번호·성별 분류 충돌·중복 트리거는 검증하여 자동 덮어쓰지 않습니다. 음성 근거가 부족하면 미지정으로 남깁니다. 포함하지 않은 자료와 API 키는 전달하지 않습니다. 현재 시안은 요청 내용과 무관한 두 캐릭터의 고정 예시이며 실제 LLM 호출은 하지 않습니다.

Fish 링크 입력: 캐릭터와 음성 추가/수정의 ID 입력에 fish.audio/m/ID, fish.audio/ko/app/m/ID/ 및 언어 경로 변형을 허용합니다. URL로 분석해 Fish Audio 호스트인지 확인하고 마지막 경로의 32자리 16진수 ID만 추출합니다. 끝 슬래시·검색 인자·해시는 제외하며 잘못된 링크는 오류로 표시하고 적용하지 않습니다. 네트워크 접근 없이 입력을 정리하며 음성의 실존 여부는 별도 조회입니다.

음성 목록 보관: 폴더와 이름을 함께 내보내는 omni-tts-library version 1 형식을 제공하고 원본 name/tag/id 배열도 가져옵니다. API 키는 내보내지 않습니다. 중복은 이름+Fish ID 기준으로 확인하며 기존 항목을 묵시적으로 덮어쓰지 않습니다.

TTS 알림: 전용 토스트 ON/OFF를 제공하며 290×62px 고정 크기, 최대 두 줄, 조금 불투명한 배경으로 표시합니다. 진행 문구는 준비 수·생성 중·대기만 표시합니다. 플로팅 뷰어의 캐시 칩에서도 진행을 확인할 수 있고 토스트를 꺼도 작업과 뷰어 진행 표시는 유지됩니다. 현재 시안의 진행 수치는 모형입니다.

03. 선생성은 보이는 화면 중심

앞뒤 준비 범위 최대 50개 · 전체/백그라운드 동시 생성 기본 5개 · 저장 기본 100MB

준비 범위는 0~50개 직접 입력. 50개는 앞뒤 합산 후보 수이며 동시 요청 수나 캐시 총개수와 다릅니다.

  1. TTS를 켜면: 현재 화면에 보이는 재생 가능한 대사를 먼저 준비. 보이는 것이 없으면 위치 확인까지 요청하지 않음.
  2. 재생 전: 화면 중앙에서 가까운 버튼부터 위·아래 양쪽으로 넓혀 최대 50개 후보 관리. 앞쪽 구간이 부족하면 뒤쪽에 남은 범위 배분.
  3. 재생 중: 사용자가 누른 구간 → 재생 중 구간의 다음 구간 → 화면에 보이는 구간 → 화면 앞뒤 가까운 구간. 앞쪽 캐시도 유지.
  4. 빠른 스크롤: 위치 수집 빈도를 제한하고 약 400ms 멈춘 뒤 선생성 순서를 재계산. 이 시간은 실제 조작 후 조정.
  5. 동시 요청: Fish 요청 관리자는 선생성·직접 재생·음성 시험을 모두 셈. 전체·백그라운드 각각 1~5개, 백그라운드는 전체 이하로 제한. 기본 5개 모두 선생성 가능. 모두 실행 중일 때 직접 재생 요청은 다음 빈 자리에 최우선 배치. 같은 구간이 이미 생성 중이면 해당 작업을 공유하며 중복 요청하지 않음. 실행 중 서버 작업이 즉시 취소되거나 자리가 즉시 비워진다고 가정하지 않음.
  6. 화면 이동: 미시작 후보는 제거. 이미 전송한 요청의 취소는 비용 환급을 보장하지 않으므로 시작 전 억제를 우선. 늦게 반환된 결과는 용량 안에서 저장하되 오래된 재생 명령은 실행하지 않음.
  7. 앱 숨김: 재생 중이 아니면 새 선생성 중지. 재생 중이면 그 재생 흐름에 필요한 구간만 준비. TTS OFF는 새 요청·재생 모두 중지.

DOM은 위치 파악용입니다. 대사와 캐시는 메시지 원문·고유 ID에 연결합니다. 가상 스크롤로 DOM이 사라져도 음성을 버리지 않습니다. 화면 밖 모든 과거 채팅을 먼저 생성하지 않습니다.

호스트에서 화면 위치를 읽을 수 없으면 마지막으로 누른 메시지 중심으로 제한합니다. 이를 전체 채팅 생성으로 대체하지 않습니다. SafeDOM으로 가능한 위치 감지부터 PocketRisu에서 검증합니다.

04. 용량 제한과 캐시 재사용

  • 압축 음성을 장치 저장소에 저장. 용량 제한에 도달하면 오래 안 쓴 파일부터 제거. 현재 재생·바로 다음 구간 보호.
  • 50개 후보 전부를 영구 보호하지 않음. 용량 부족 시 선생성 범위 축소, 너무 큰 음성은 보관 생략.
  • 재생 중·가까운 다음 음성만 메모리에서 디코딩. 모든 파일을 AudioBuffer로 올리지 않음. 객체 URL 해제 및 메모리 상한 관리.
  • 동일 캐시 키의 진행 중 요청은 하나로 합침. 여러 버튼이 같은 음성을 요청해도 중복 과금 요청 방지.
  • 번역 키: 원문 + 목표 언어 + 제공자/모델 + 번역 규칙 버전 + 필요한 문맥 식별값.
  • 음성 키: 읽을 번역문/원문 + Fish ID + 억양 + 합성 모델 + 형식 + 합성 옵션.
  • 배속·기기 볼륨은 로컬 재생 옵션으로 적용해 음성 재생성 방지. 합성 옵션이 바뀌면 별도 키 사용.
  • 대사 수정·음성 변경·언어 변경 시 해당 구간만 새 키로 준비. 메시지 삭제 시 늦은 결과의 잘못된 연결 방지.
  • 번역 텍스트도 별도 용량·개수 제한. 채팅 캐시와 전체 캐시 비우기 구분. 캐릭터·음성 목록·설정은 유지.

캐시를 지운 뒤 다시 듣는 구간은 재생성 비용이 들 수 있습니다. 먼저 생성했다가 듣지 않은 음성도 비용이 발생하므로 선생성 범위를 조절할 수 있게 합니다.

05. 새 캐릭터만 짧게 판별

완성 메시지 → 화자명 수집 → TTS 트리거워드 대조 → 미등록만 LLM → 음성 배정.

글로벌 캐릭터와 자료에서 가져오기

TTS 캐릭터는 현재 채팅 또는 글로벌 범위로 저장합니다. 캐릭터 ID와 성·이름·각 표기 변형을 따로 저장합니다. 같은 저장 범위에서 이름이 같으면 통합하되, 양쪽 성이 명시되어 서로 다르면 통합하지 않습니다. 성이 비어 있고 일치 후보가 하나면 통합할 수 있지만, 김민지·이민지가 함께 있는데 민지만 들어오면 미확정으로 남깁니다. 빈 성을 연결 고리로 서로 다른 성의 캐릭터를 연쇄 통합하지 않습니다. 별칭·트리거워드 중복만으로는 통합하지 않습니다. 화자 연결은 정확한 전체 이름을 먼저 찾고, 없을 때 별칭 후보를 찾습니다. 둘 이상이면 첫 번째를 고르지 않습니다. 현재 채팅 우선은 동일 인물로 확인된 글로벌 항목의 설정에만 적용하고 다른 인물의 별칭 충돌을 숨기지 않습니다. 음성 고정은 선택된 유효 캐릭터 설정에 적용합니다. 글로벌 편집은 다른 채팅에도 영향을 준다는 범위 표시를 유지하며 기존 삽화 전역 저장소와 별도로 관리합니다.

‘LLM한테 시키기’에서 로어북·페르소나·삽화 캐릭터 목록을 복수 선택하고 등록 범위를 정합니다. 읽을 로어북 항목을 선택·제한한 뒤 필요한 이름·설명·키만 보내고 원본 전체나 이미지 바이트는 보내지 않습니다. 삽화 자료는 이름·별칭을 직접 재사용하고, LLM은 설명 해석과 필요한 음성 선택에만 활용합니다. 자료 속 명령은 실행하지 않고 추출 대상으로만 취급합니다.

클릭에 따른 일괄 가져오기는 일반 메시지의 신규 화자 자동 배정과 별개입니다. LLM 결과는 요청 자료에 근거한 이름·별칭만 허용하고 개수·길이·중복·후보 번호를 검증합니다. 결과 목록에서 선택 후 등록하며 기존 캐릭터·고정 음성을 덮어쓰지 않습니다. 성별이나 음성 근거가 없으면 선택 대기로 둡니다. 자료/범위가 바뀌면 이전 결과 승인을 무효화합니다. 통합 시 기존 캐릭터 ID·고정 음성·개별 음량을 보존하고 별칭과 표기 변형을 합칩니다. 수정 제안은 캐릭터 ID로 적용합니다. 성은 한국어 이름의 첫 글자만으로 추측하지 않습니다. 삽화 캐릭터의 성·이름 필드 구조를 참고하되, 성이 달라도 이름만으로 합치는 기존 삽화 저장 로직은 TTS에 재사용하지 않습니다. 시안은 고정 예시로 범위·중복·검수 흐름만 재현합니다.

별칭은 이름 전체를 기준으로 공백·유니코드 표기를 정리합니다. ‘린’이 ‘하린’ 안에 포함되어 있다고 같은 사람으로 합치지 않습니다. 두 인물의 별칭이 충돌하면 자동 연결하지 않습니다.

LLM에는 미등록 이름·관련 대사 일부·연관 로어 발췌·캐릭터 설명/페르소나의 필요한 정보만 전달합니다. 호스트가 실제 활성 로어를 제공하는지 확인합니다. 자체 키 매칭 결과를 ‘실제 활성 로어’라고 부르지 않습니다.

음성 후보는 번호와 짧은 특징으로 압축합니다. 여성은 앞 번호, 남성은 1001부터, 미지정는 별도 대역으로 제안합니다. 요청 당시 번호 목록을 고정해 삭제·정렬 때문에 진행 중 응답이 다른 음성에 연결되지 않게 합니다. Fish ID와 프리셋의 긴 이름은 보내지 않습니다.

후보 예:
1|여|청년,차분함,부드러운
2|여|청년,밝은,명랑한
1001|남|청년,열정적인,진지한
응답 예:
[["하린",1,["린"]],["도윤",1001,[]]]

이름은 요청한 화자 안에서만, 번호는 제공한 후보 안에서만 받아들입니다. 번호 대역만으로 성별 오류가 완전히 사라지지는 않습니다. 확실한 성별은 후보를 코드에서 제한하고, 근거가 없거나 결과가 어긋나면 미확정으로 남깁니다. 기본은 TTS 자동 음성 배정 설정을 따릅니다. 자동 ON이면 미등록 화자만 배정하고 기존 배정은 재사용합니다. 개별 음성 고정을 직접 켠 캐릭터만 자동 변경에서 제외합니다. 자동 OFF이면 신규 배정은 수동 대기이며 기존 음성 재생은 유지합니다.

새 화자가 없으면 음성 배정 LLM은 0회. LLM 번역을 켜면 새 대사는 번역 호출이 필요합니다. 메시지의 여러 대사를 짧은 구간 ID와 함께 묶어 번역하고, 결과 ID·개수·순서를 검증합니다.

06. 이름·억양 모듈과 안전한 표시

제공한 이름억양 파일 기반 규칙 초안은 출력 형식만 요청합니다. 가져오기·실제 호스트 검증 전이며, 재생/화면 숨김 코드는 아직 없습니다.

하린 (soft tone): "조금만 더 읽고 갈래?"
도윤 (curious): "어떤 이야기인데?"
이름·억양 표식이 없는 일반 본문은 나레이션.
  • 억양은 짧은 Fish 호환 표현 1~2개를 유도. 일반 한국어 억양은 로컬 사전으로 변환. 알 수 없는 값은 중립으로 처리하며 진단 가능하게 함. 매번 LLM으로 억양을 재분석하지 않음.
  • 이름·억양 숨김은 표시 단계에서만 적용. 저장된 메시지나 삽화 원문을 덮어쓰지 않음.
  • 모듈 HTML에 script·onclick·onmouseover·JavaScript URL을 넣지 않음. 검증된 구간 ID만 버튼에 넣고 플러그인이 SafeDOM으로 이벤트 연결. 재생 버튼은 닫는 큰따옴표 직후 인라인 배치. 기존 문단·강조·링크·삽화 DOM을 통째로 재작성하지 않고 텍스트 구간과 표식만 연결. 여러 텍스트 노드에 걸친 대사는 별도 구간 매핑으로 처리하며 식별 실패 시 원문 유지.
  • CSS는 한 번만 등록. Risu 클래스 접두사·허용 속성·메시지 재렌더링 후 버튼 연결을 실제 호스트에서 확인.
  • 모델의 텍스트를 HTML 속성이나 실행 가능한 CBS로 그대로 넣지 않음. 텍스트·속성 각각 이스케이프.

스트리밍과 정규식

완성 메시지는 한 번 순회하는 파서로 분리합니다. 표시 중에는 완성된 줄만 처리하고 기존 처리 결과를 재사용합니다. 닫히지 않은 따옴표·괄호는 원문으로 남깁니다. 중첩 반복·무제한 앞뒤 탐색은 쓰지 않고 줄/이름/억양 길이 제한을 둡니다.

코드 블록·이미지 표식·상태창·HTML 속성의 따옴표는 대사에서 제외합니다. 초기 구현의 유료 선생성은 답변이 완성된 뒤 시작하고, 스트리밍 중에는 가벼운 표시 처리만 하는 안입니다.

사용자가 말한 5개 제한에 맞춰 시안 상한은 5입니다. Fish는 계정 등급별 한도가 있으며 다른 API 키의 사용량도 공유합니다. 다른 앱 사용분을 플러그인이 모두 알 수는 없습니다. 429는 횟수를 제한해 간격을 늘리며 재시도, 인증·잔액 오류는 자동 반복하지 않습니다. 요청 한도

번역 묶음 처리

Google 무료 번역은 대사별로 처리할 수 있고, LLM 번역은 주변 후보 중 번역 캐시가 없는 여러 구간을 한 요청으로 묶습니다. 항목 수·입력 및 출력 토큰 상한을 두어 전체 채팅을 한꺼번에 보내지 않습니다. 간단한 번호와 원문만 전달하고 결과도 번호→번역문 JSON으로 받습니다. 이름·Fish ID·억양은 별도로 유지하여 번역하지 않습니다. 사용자가 직접 재생을 누른 구간은 묶음이 채워질 때까지 기다리지 않고 우선 처리합니다. 실행 중인 같은 번역은 공유합니다. 누락·중복·알 수 없는 번호는 검증에서 걸러 실패한 구간만 제한적으로 재요청합니다. 화면 이동 시 시작하지 않은 묶음은 다시 구성하며 기존 번역/음성 캐시는 재사용합니다.

LLM 정리 요청의 최소 출력

선택된 항목이 있으면 그 항목, 없으면 현재 필터 결과만 정리 대상으로 고정합니다. 요청마다 짧은 음성 번호·폴더 번호를 발급하고 내부 항목 키와 연결한 표를 보관합니다. 입력에는 분류에 필요한 이름·간단한 태그·기존 폴더만 포함하며 Fish ID는 보내지 않습니다. 출력은 예를 들어 {"folders":{"1":"귀멸의 칼날"},"moves":[[1,1],[2,1]],"renames":[[1,"시노부"]]} 형태로 제한합니다. 기존 이름·태그·ID를 반복 출력하지 않고 새 폴더명·변경할 이름만 필요할 때 출력합니다. 변하지 않은 항목과 빈 필드는 생략합니다.

검수 화면은 플러그인이 번호를 원래 항목에 연결해 만듭니다. 알 수 없는 번호·중복/충돌하는 변경·길이 초과를 거부하고 폴더 이름과 음성 이름은 텍스트로만 표시합니다. 요청 중 정렬이 바뀌어도 요청 당시 대응표를 사용하며, 대상이 삭제되거나 사용자가 값을 바꿨으면 충돌로 표시합니다. 적용 전에는 목록을 바꾸지 않고, 자동 삭제·ID 변경·음성 병합은 허용하지 않습니다. 새 음성을 추가하는 변환은 아직 대응표가 없으므로 입력에서 확인한 name/tag/id가 필요하며 정리 전용 번호 출력과 구분합니다. 시안은 LLM 호출 없이 고정 정리 예시를 표시합니다.

Fish ID의 태그와 억양

인증된 GET /model/{id}에서 title, tags, description, cover_image, languages 등을 조회할 수 있습니다. 별도의 성별 필드는 확인되지 않았습니다. 명확한 성별 태그만 분류에 사용하고 없거나 충돌하면 ‘미지정’. 태그 입력은 선택 사항이며 사용자가 수정한 값을 자동 덮어쓰지 않습니다. 캐릭터 이름과 Fish 음성 제목은 별개로 보존합니다. Fish 음성 조회

이름억양의 ‘속삭임’ → [whispering], ‘기쁨’ → [happy]처럼 S2 입력 앞에 변환합니다. 이름을 음성으로 읽지 않으며 번역 후에도 억양을 유지합니다. 자연어 큐도 지원하지만 음성별 표현 차이가 있어 청취 검증이 필요합니다. 구형 S1은 괄호 문법이므로 모델별 변환기를 분리합니다.

JEV 연결과 분위기 태그 기반 음성 선택

모델 설정에 JEV 전용 연결을 추가합니다. OpenRouter 기본값은 모델 typesafe/jev-1.13, URL https://openrouter.ai/api/alpha/decisions입니다. TypeSafe 공식은 모델 jev-1.13.0, URL https://api.typesafe.ai/v1/systemone를 제안합니다. 모든 사이트에서 모델명·전체 요청 URL을 직접 수정할 수 있으며 ‘기타 사이트’와 API 형식(Decisions / System One)을 제공합니다. 사이트별 입력값은 각각 보존하고 키도 사이트별 연결에만 사용합니다. 시안에서는 사이트 전환 시 키 입력을 비우며 실제 저장·요청을 하지 않습니다. 다른 사이트가 해당 API 형식을 지원하는지는 실제 응답 스키마로 확인합니다. 일반 chat/completions 호환만으로 JEV 연결 가능하다고 가정하지 않습니다. 캐릭터별 tags를 트리거워드와 분리합니다. 예: 청년·중년·여성·차분한·파워풀한. 이름·트리거워드는 화자 연결에, 분류·분위기는 음성 후보 선택에 씁니다. 사용자가 직접 입력하거나 자료를 읽는 LLM이 함께 제안합니다. 명시적 성별과 태그가 충돌하면 확인 대상으로 남기며 외형만으로 성별·목소리를 단정하지 않습니다. 태그가 없는 기존 캐릭터는 빈 목록으로 취급합니다.

캐릭터 팝업 음성 프리셋에는 ‘음성 목록에서 선택 / JEV한테 시키기 / LLM한테 시키기’를 제공합니다. 자동 배정의 음성 선택 모델도 LLM/JEV 중 고릅니다. JEV는 생성형 텍스트 모델이 아니므로 이름·별칭 새로 작성, 번역, 캐릭터 추가·수정 문장 생성은 LLM이 맡습니다. JEV는 주어진 캐릭터 정보와 후보 음성의 짧은 태그를 보고 Choice로 번호를 선택합니다. API의 choice/probabilities/confidence를 검증하고 앱에서는 선택된 번호를 원래 음성 ID에 연결합니다. JEV 판단 방식

요청별 캐릭터·음성 번호 대응표를 유지하고, 긴 Fish ID를 반복 출력시키지 않습니다. 성별이 명확한 경우 코드에서 후보를 제한하고 ‘선택 보류’도 후보로 둡니다. 낮은 확신·일치 후보 없음·삭제된 후보·잘못된 번호는 미확정으로 남기고 몰래 다른 유료 모델을 호출하지 않습니다. 확신 기준은 실제 음성 매칭 검증으로 정합니다. 태그 추출과 음성 선택이 모두 필요하고 LLM 선택 모드라면 한 번의 LLM 결과에 함께 받습니다. 기존 태그와 배정이 유효하면 재호출하지 않습니다. 캐릭터 팝업의 JEV/LLM 추천이 도착하면 첫 번째 유효 후보를 즉시 선택해 편집 초안에 반영합니다. 추천 목록은 열린 상태로 두고 현재 선택을 강조하며 다른 후보를 누르면 교체합니다. 저장 전 취소하면 기존 캐릭터 음성은 유지합니다.

JEV로 선택 캐릭터 일괄 음성 배정

캐릭터 탭의 LLM 버튼 옆에 ‘JEV한테 시키기’를 둡니다. 누르면 타일을 터치/클릭해 다중선택할 수 있고 Shift 범위 선택도 제공합니다. 목록 아래 고정 작업바에는 선택 중인 인원, 음성 후보 폴더(전체 폴더·미분류·사용자 폴더), 전체 선택·선택 해제·취소·선택 버튼을 표시합니다. 전체 선택은 현재 검색·범위에 표시된 타일에 적용하며 선택 개수는 숨겨진 선택까지 포함합니다. 취소하면 음성을 바꾸지 않습니다.

‘선택’은 선택한 캐릭터들의 음성 배정을 실행합니다. 요청 당시 캐릭터와 폴더 안의 후보를 번호로 고정하고 캐릭터별 Choice 질문을 묶습니다. 공급자 크기 제한에 맞춰 묶음을 나누고 음성 고정은 제외합니다. 폴더에 후보가 없거나 분류에 맞지 않으면 기존 음성을 유지합니다. 응답은 요청 스냅샷과 대조하고 삭제/변경된 캐릭터는 덮어쓰지 않습니다. 시안에서는 분류가 맞는 폴더 내 첫 음성으로 배정 동작만 시험하며 태그 적합도 판단·JEV 요청은 하지 않습니다.

LLM으로 현재 캐릭터 전체 수정·추가

자료 가져오기와 자유 요청을 캐릭터 탭 ‘LLM한테 시키기’ 하나로 통합합니다. 요청을 비우고 참고 자료를 선택하면 자료에서 가져오는 용도로 사용할 수 있습니다. 이 창은 현재 채팅 및 글로벌 TTS 캐릭터 전체를 검토할 수 있습니다. ‘기존 캐릭터 전체 수정 제안’과 ‘새 캐릭터 추가 제안’을 각각 켜고, 로어북·페르소나·삽화 목록 포함 여부를 지정합니다. 신규 등록 범위는 별도로 선택하며 기존 항목은 저장 범위를 유지합니다. 팝업은 요청, 작업 토글, 참고 자료 토글, 신규 등록 범위·LLM, 결과 순서로 배치하며 반복 안내는 접힌 도움말로 모읍니다. 취소·제안 받기·선택 적용은 하단에 고정합니다. 제안은 이름·별칭·분위기 태그·음성의 변경 전후와 추가/수정을 구분해 보여주고 체크한 항목만 적용합니다. 삽화 캐릭터 원본·로어북·페르소나는 변경하지 않습니다.

LLM에는 기존 캐릭터 번호, 이름/별칭/태그, 관련 자료와 음성 후보 번호만 전달합니다. 출력 예는 {"u":[[1,{"tags":["청년","차분한"],"v":2}]],"a":[["서윤",["Seoyun"],["여성","차분한"],1]]}로, 기존 항목은 바뀐 필드만 반환합니다. 고정된 음성·개별 음량은 유지하고 이름/별칭 중복, 허용하지 않은 번호, 중복 수정, 삭제 지시, 검토 중 사용자가 바꾼 항목을 검증합니다. 새 응답에 없다는 이유로 기존 캐릭터를 삭제하지 않습니다. 현재 HTML은 고정 추가·수정 예시와 추천 후보 선택을 검수하는 모형으로, JEV/LLM을 실제 호출하거나 태그 적합도를 계산하지 않습니다.

Risu 모델과 여러 음성 가져오기

새 화자 음성 배정·번역·목록 변환 각각 Risu 메인(model), 기본 보조(submodel), 감정(emotion), 번역(translate), 메모리(memory), 기타(otherAx) 또는 직접 API 연결을 선택할 수 있게 합니다. 현재 공통 변환기의 aux는 otherAx로 매핑되므로 기본 보조와 기타를 구분하는 실제 호스트 호출 검증이 필요합니다. 선택한 모델이 없으면 연결 필요 상태를 표시하며 삽화 모델로 대체하지 않습니다.

사이트에서 복사한 목록은 사용자가 ‘LLM으로 추가’를 눌렀을 때만 변환합니다. 붙여 넣은 문서는 데이터로만 취급하고, 결과는 name/tag/id 배열로 제한합니다. ID가 없으면 만들어내지 않고 확인 필요로 남깁니다. ID 형식·입력에 실제 존재하는 ID·개수·길이·중복을 검증하고 결과를 선택하여 추가합니다. 실제 음성 존재/접근 가능 여부는 Fish 조회로 별도 확인합니다. 기존 항목을 자동 덮어쓰지 않습니다. 시안은 예시 또는 JSON만 검수하며 LLM 호출은 하지 않습니다.

자동 음량 보정에 캐릭터별 수동 보정을 더합니다. 체감 음량을 완전히 같게 보장하지는 않으므로 실제 청취 검증이 필요합니다. 초기에는 구간별 음성 파일로 만들어 이동·취소·캐시 처리를 단순하게 합니다.

브라우저 음성 재생 활성화

Chrome은 사용자 동작 없이 시작하는 소리 재생을 제한할 수 있습니다. 시스템 권한창·알림 권한·마이크 권한을 요청하는 기능이 아닙니다. TTS 탭과 채팅 화면에 ‘음성 재생 활성화’ 버튼을 제공하고, 필요할 때 앱 자체 안내창에서 사용자가 직접 눌러 시작하게 합니다. Chrome 공식 자동 재생 정책

  1. 백그라운드 음성 생성과 재생 활성화는 분리. 음성을 미리 만들어도 사용자가 활성화하기 전 자동/마우스오버 재생은 대기.
  2. 사용자의 실제 클릭 처리 안에서 오디오 컨텍스트 생성·resume 또는 미디어 play를 시작. 네트워크 요청을 기다린 뒤 사용자 활성화를 얻었다고 가정하지 않음.
  3. play/resume의 성공 결과와 실제 오디오 상태를 확인한 뒤 ‘활성화됨’ 표시. NotAllowedError나 suspended 상태면 ‘활성화 필요’로 복귀. 실제로 재생되지 않는데 일시정지 아이콘을 표시하지 않음.
  4. Risu 호스트의 버튼 클릭을 비동기 SafeDOM 브리지로 전달할 때 사용자 동작이 플러그인 iframe까지 유효한지 검증. 필요하면 실제 오디오를 소유한 플러그인 iframe의 설정창에서 직접 활성화하도록 안내.
  5. iframe의 autoplay 위임·브라우저 정책에 막힌 경우 버튼 하나로 무조건 해결된다고 약속하지 않음. 지원 여부와 재시도 안내를 제공.
  6. 페이지 새로고침·플러그인 재시작·컨텍스트 재생성 뒤 상태 재확인. 영구 허용 플래그만 저장하고 성공으로 간주하지 않음.

시안의 활성화 창은 이 흐름의 모형입니다. 실제 오디오나 브라우저 권한을 변경하지 않습니다.

공통 재사용은 저수준 HTTP·LLM 호출·호스트 도구에 한정합니다. 삽화 태거 프롬프트·job 잠금·토스트·card.power에 의존하지 않습니다. TTS 캐릭터 저장은 별도이며 삽화 캐릭터·메타데이터는 이미지 표시와 삽화 대사 연결에 읽기 전용으로 참조합니다. 새 라우트는 기존 router 규칙에 맞게 등록하고 변경된 동작을 패리티 시나리오에 명시합니다.

옴니 삽화 텍스트 읽기

재생과 읽기에 독립 토글을 둡니다(시안 기본 ON). 기존 Omni 삽화 모듈의 정규식·HTML·저장 내용은 변경하지 않고, OmniTTS 플러그인의 삽화 연결부가 기존 data-inlay-inline-shot / data-inray-asset 식별자로 표시된 삽화를 찾아 아래에 TTS 소유 재생 버튼을 붙입니다. 모듈 HTML에 스크립트를 넣지 않고, 허용된 호스트 DOM API로 이벤트를 연결합니다. 실제 Risu에서 식별자 보존·DOM 삽입·재렌더링을 검증한 뒤 호환을 확정합니다.

char1·char2는 음성 이름이 아니라 캐릭터 슬롯입니다. 현재 이미지의 GenerationImageData.characters[]에 저장된 이름과 같은 슬롯의 recipe.characters[].prompt 또는 v4_prompt.caption.char_captions[].char_caption을 연결합니다. 가능하면 기존 정규화 함수와 구조화된 speech 데이터를 사용하고, 저장 레시피에서는 korean text: 대사를 읽습니다. 쉼표가 대사 안에도 들어가므로 단순 쉼표 분리는 금지하며, 대사와 후속 태그의 경계가 불명확하면 읽기 대상에서 제외합니다. OCR이나 외형 태그 읽기는 하지 않습니다.

이름을 TTS 캐릭터의 이름·트리거워드와 정규화 후 전체 일치로 대조하고 기존 채팅/글로벌 우선순위를 따릅니다. 미등록 화자는 기존 신규 화자 배정 흐름에 합치고 중복 호출하지 않습니다. 여러 캐릭터에 매칭되면 임의로 선택하지 않습니다. 대사·이름이 없거나 음성이 미지정이면 해당 슬롯을 건너뜁니다. 삽화의 재생 아이콘은 읽을 수 있는 슬롯이 있을 때 표시합니다. 아이콘은 계속 유지하고, 누르면 우측에 캐릭터 이름 칩만 한 줄로 표시합니다. 그림 아래에 대사 텍스트를 다시 나열하지 않습니다. 삽화 대사는 본문 음성 목록·자동 재생·본문 이어 읽기에서 제외합니다. 명시적으로 삽화 버튼을 누를 때만 삽화 전용 재생 대상으로 전환하고 끝나면 멈춥니다. 단일 오디오 제어를 공유하므로 본문과 삽화가 겹쳐 재생되지는 않습니다. 원래 대사 순서가 저장되지 않았다면 그림 속 공간 배치를 읽기 순서로 추정하지 않습니다.

기존 번역·Fish 큐·선생성·캐시·플로팅 뷰어를 함께 사용합니다. 캐시 키는 메시지 번호가 아니라 음성 ID·실제 발화 텍스트·억양·모델 등 생성 조건으로 구성해 본문과 삽화의 동일 대사도 재사용합니다. 메타데이터에 억양이 없으면 중립으로 읽고 LLM으로 임의 생성하지 않습니다. 현재 표시 이미지가 리롤/히스토리 전환으로 바뀌면 해당 이미지 기준으로 다시 연결하고, 토글 OFF·채팅 전환·삭제 시 소유 버튼과 진행 작업을 정리합니다. 이미 표시된 삽화는 삽화 Power OFF여도 TTS ON이면 읽을 수 있습니다.

목록 조회는 imageMeta/imageLocation 등 가벼운 정보로 처리하고, PNG/WebP 내장 메타데이터가 꼭 필요할 때만 보이는 후보 이미지의 바이트를 지연 조회하여 이미지 버전별로 재사용합니다. 목록 전체에 idbGet('images', …)를 호출하지 않습니다. 채팅 HTML에 도서관 삽화 예시와 그림 아래 재생 버튼, char1/char2 캐릭터 칩을 제공합니다. 그림 아래 재생 아이콘을 누르면 그 우측에 캐릭터 칩이 생기며, 생성 대기/완료 후 자동 재생하는 흐름을 플로팅 뷰어에서 시험할 수 있습니다. 본문 음성 목록에는 삽화 대사가 추가되지 않습니다. 검수용 그림은 SVG이며 대사는 고정 데이터입니다. 실제 이미지 메타데이터 추출과 음성 재생은 아직 미연결입니다.

삽화 클릭 요청의 순서: 캐시가 있으면 즉시 재생하고, 없으면 우선 작업으로 대기열에 넣습니다. 본문 백그라운드 생성과 삽화 생성은 같은 동시 요청 상한을 사용합니다. 5개가 진행 중이면 6번째 요청을 보내지 않고, 하나가 끝나 자리가 나는 즉시 대기 중인 클릭 요청을 일반 선생성보다 먼저 시작합니다. 모든 백그라운드 요청이 끝날 때까지 기다리지 않습니다. 동일 음성을 이미 생성 중이면 그 작업을 공유하고 우선순위만 올립니다. 생성 완료 후에도 최신 재생 요청인지 확인한 뒤 자동 재생하며, 정지·다른 대상 클릭·TTS OFF 뒤 늦게 도착한 음성은 임의 재생하지 않습니다. HTTP 오류 여부와 별개로 슬롯은 종료 시 반환하고 429는 제공자 대기 정책에 따라 처리합니다. HTML에서는 슬롯 반환과 생성 완료를 타이머로 모사하며 실제 Fish 요청은 없습니다.

폴더 JSON 공유

음성 목록의 폴더 + 옆에 폴더 ⋯ 메뉴를 둡니다. 선택 폴더 전체의 이름·음성 이름·태그·Fish ID를 JSON으로 내보냅니다. 검색으로 일부만 보이더라도 폴더 전체를 내보내며 전체 음성은 기존 파일 메뉴를 사용합니다. 불러오기는 폴더 JSON 또는 기존 name/tag/id 배열·음성 라이브러리 JSON을 지원하고, 파일을 검증한 뒤 새 폴더 이름을 입력해 적용합니다. 기존 폴더 이름과 겹치면 이름을 다시 지정합니다. 다른 폴더에 같은 음성이 있어도 새 폴더에 복사하며 파일 내 동일 이름/ID 중복만 한 번 넣습니다. 취소·잘못된 파일은 목록을 변경하지 않습니다. 캐릭터 배정·나레이션 지정·API 키·내부 ID는 공유하지 않습니다. 현재 시안에서는 JSON 다운로드/불러오기와 임시 목록 변경을 시험할 수 있으며 영구 저장은 미연결입니다.

목록 검색과 검수 화면

캐릭터 목록 상단은 PC에서 제목·검색·범위·작업 버튼을 한 줄로 배치하고 좁은 화면에서는 줄바꿈합니다. 음성 검색은 |로 또는, &로 모두 포함을 표현합니다. &를 먼저 묶으므로 여성 & 차분 | 남성 & 밝은은 두 조건 그룹 중 하나가 맞으면 표시합니다. 괄호와 정규식은 해석하지 않으며 이름·태그·Fish ID를 문자 그대로 검색합니다. 빈 조건은 무시하고 입력은 500자로 제한합니다. 우측 ×는 검색어만 비우고 성별·폴더 선택은 유지합니다. 검수용 상단 ‘채팅 시안’으로 메시지·플로팅 뷰어에 진입하며 제품의 실제 설정에는 이 검수 버튼을 포함하지 않습니다. 검수 전용 이동 버튼·새 답변 시뮬레이션·알림 시험·샘플 입력·초안 다운로드는 분홍색으로 구분하고 툴팁에 검수 전용임을 표시합니다. 실제 제품에 남을 재생·연결 확인·캐릭터 편집 기능은 지금 모형으로 동작하더라도 기존 색을 유지합니다.

캐릭터 타일: 한국어·영어 이름과 트리거워드를 NFKC·공백·대소문자 정리 후 전체 일치로 대조합니다. 한 명과 일치하면 참조/레퍼 이미지의 작은 썸네일을 표시하며, 여러 명이면 선택 대기로 남깁니다. 삽화 Power OFF에서도 조회 가능. 목록마다 원본 이미지를 디코딩하지 않고 메타데이터 조회와 보이는 타일의 썸네일만 지연 로딩합니다. TTS 목록의 편집·삭제가 삽화 캐릭터를 변경하지 않습니다. 현재 시안 이미지는 실루엣 예시이며 사용자 데이터와 미연결입니다.

플로팅 뷰어: 배경 불투명도 55%의 반투명 뷰어, 302px 기본 폭, 주요 재생 버튼 44px. 헤더에는 제목 대신 대기·재생·일시정지 상태 아이콘과 나레이션 ON/OFF, 배속/볼륨 통합 칩과 현재 메시지 음성 목록 칩을 배치합니다. 아이콘은 툴팁과 접근성 이름을 제공하며 펼침 칩은 한 번에 하나만 엽니다. 헤더 우측 접기 버튼 바로 왼쪽에 설정 아이콘을 두고 TTS 설정 탭으로 바로 이동하게 합니다. 최소화 상태에서는 + 하나만 남깁니다. 화자·억양·대사는 한 줄, 이전·재생·다음은 중앙, 정지는 우측 끝에 둡니다. 최소화하면 기존 − 버튼 위치에 38px의 + 버튼 하나만 남기고, 펼치면 원래 위치를 복원합니다. 배속과 볼륨은 통합 칩 하나로 함께 펼칩니다. 메시지 DOM이 가상 스크롤로 사라져도 고유 ID로 현재 목록 유지. 나레이션 OFF면 자동 시작·다음/이전·연속 재생·선생성에서 제외하고 음성 목록 항목과 인라인 재생 버튼도 숨깁니다. 채팅 본문은 유지하며 나레이션 칩으로 다시 켤 수 있습니다. 음성 목록에서 나레이션 음성을 바로 지정합니다. 모바일에서 목록 펼침·가로 화면·터치 영역을 검증합니다.

뷰어 이어 읽기: 재생 버튼 묶음 왼쪽에 ON/OFF 토글 아이콘을 두고 설정창의 다음 구간 이어 읽기 값과 동기화합니다. OFF면 직접 누른 본문/삽화 구간 하나가 끝난 뒤 멈추고 ON이면 해당 재생 목록 안에서 다음 구간으로 이동합니다. 새 답변 완료 후 자동 재생은 별도의 설정으로 유지합니다. 현재 재생은 토글 변경으로 다시 시작하지 않고 구간 종료 때 최신 값을 확인합니다.

뷰어 상태 저장: 실제 구현에서는 나레이션·이어 읽기·뷰어 표시 여부·배속·볼륨을 TTS 설정 저장소의 동일한 값으로 읽고 씁니다. 커스텀 배속 목록(쉼표로 입력, 기본 0.5·0.75·1·1.25·1.5·1.75·2·2.5·3·3.5)도 같은 저장 경로를 사용합니다. 목록은 양수 숫자만 허용하고 중복 제거·오름차순으로 정리하며 빈 입력은 기본 목록을 뜻합니다. 목록을 바꿔도 현재 배속은 유지하고 목록에 없는 현재값은 임시 선택으로 표시합니다. 실제 호스트에서 지원하지 않는 배속은 제한을 안내합니다. 배속/볼륨·캐시·음성 목록의 펼침 상태(한 번에 하나)와 최소화 여부도 저장하고 재실행/뷰어 재생성 때 복원합니다. 화면에는 변경을 즉시 반영하고 공통 저장 경로에서 지연 저장합니다. 삽화 전원과 독립적으로 저장하며 저장 실패는 알립니다. 위치를 복원한다면 화면 범위 안으로 보정합니다. 재생 중 여부·현재 오디오 요청·대기 작업은 영구 복원하지 않습니다. 시안은 같은 화면 세션에서 설정과 뷰어 값을 동기화하며 실제 장치 저장은 아직 연결하지 않았습니다.

TTS 토스트: 반투명, 포인터 통과, 위치별 겹침 방지. 준비 완료/전체, 진행 중, 대기, 실패 수와 실제 단계(번역/생성)를 작업 상태에서 집계. 스크롤로 후보가 바뀌면 현재 범위 기준임을 표시하고 변경 알림 빈도를 제한합니다. 시안의 진행 수치는 타이머 예시입니다.

현재 src/services/tts.ts는 card.power와 tts_on을 함께 검사하고 이미지 박제 후 읽기를 호출합니다. 구현 때 이 경로를 이관하여 이중 재생을 없애고 TTS 전용 완료 메시지 처리로 바꿉니다.

‘omnitts.data’는 전용 데이터 구역의 가칭입니다. 전용 장치 저장 키 onx_tts_*와 채팅/캐릭터 범위 ID를 제안합니다. 실행용 매핑을 메인 대화의 로어북에 매번 주입하지 않습니다. 기존 삽화 키는 유지하며 별도 JSON 내보내기를 제공합니다.

설정창은 플러그인 iframe DOM, 채팅 버튼은 SafeDocument/SafeElement를 통한 호스트 DOM입니다. 최초 재생 권한·마우스오버 재생은 실제 브라우저에서 확인하며 필요하면 첫 클릭으로 음성을 활성화합니다. Risu 공식 플러그인 문서

채팅 전환·편집·삭제·재생 대상 변경마다 작업 세대와 메시지 ID를 확인합니다. 늦게 온 음성이 엉뚱한 채팅에서 재생되지 않게 합니다. 실제 재생 제어는 한 곳이 소유하고 음성 시험도 같은 재생 제어를 통과합니다. 본문·삽화·미리듣기 모두 단일 오디오 출력과 재생 요청 번호를 공유합니다. 새 재생 요청은 기존 오디오를 즉시 멈추고 요청 번호를 갱신합니다. 모든 비동기 단계(번역·생성·디코딩·play 완료·종료 이벤트)는 번호와 채팅/메시지를 다시 확인하며, 마지막 요청만 재생할 수 있습니다. 같은 구간 연타는 중복 시작하지 않습니다. 정지·일시정지·TTS OFF·대상 삭제/전환은 이전 재생 예약과 활성화 대기도 무효화합니다. 취소된 요청의 늦은 응답은 캐시 저장만 가능하며 자동 재생하지 않습니다. Fish 생성 동시 요청 제한은 별도 관리하고 실행 중 요청의 자리는 실제 종료/실패가 확인될 때만 반환합니다. 시안 검사는 모의 타이머로 연타·늦은 완료·미리듣기 전환을 재현하며 실제 오디오 중첩 여부는 호스트에서 별도 검증합니다.
